# HalfHalf 前端重设计说明（给实现方 / 其他 AI 看的规范）

本文件配合 `HalfHalf 工作台.dc.html`（可运行的高保真设计稿）使用。设计稿是**视觉与交互的唯一真相**，
本文件解释**为什么这样设计**、每个像素对应哪段旧代码、以及如何把它落回 `packages/web` 的 React 代码。

**硬约束：功能一个都不能少，后端接口一个都不改。** 这次只换外观与信息编排。

---

## 1. 源代码基线（重设计前的界面）

| 文件 | 现状 |
| --- | --- |
| `packages/web/src/components/Layout/AppLayout.tsx` | 48px 白色 header（`📄 HalfHalf` + 一句副标题），下面一个 `flex:1` 的 main |
| `packages/web/src/components/Scene/ScenePanel.tsx` | 左右两栏（各 `flex:1`）。左栏自上而下：ChatIntake、参数行、高级选项折叠、fixtures 速载、AI 设置折叠、AI 建议列表、Markdown textarea、错误、结果结论 + `<details>` 引擎详情 + `<details>` 块诊断、`<details>` 会话历史。右栏：PDF 下载链接 + `<iframe>` 预览，未生成时虚线占位 |
| `packages/web/src/components/Scene/ChatIntake.tsx` | `<details open>` 里的原始材料 textarea + 转换按钮 + SSE 流式预览 + 体检结论 + 采用按钮 |
| `packages/web/src/styles/global.css` | 旧 token：`--color-primary:#4f46e5`、bg `#f0f2f5`、radius 8px、系统字体 |
| `packages/web/src/types/index.ts` | `SceneResult` / `SceneDiagnostics` / `BlockSuggestion` 等响应类型 |
| `packages/web/src/api.ts` | `apiFetch`：带 `x-access-code`，401 时 prompt 口令并重试 |

**旧界面的问题**：所有二级信息（引擎详情、块诊断、会话历史、AI 建议、AI 设置、高级选项、材料转换）
都堆在左栏、用 `<details>` 原地展开 —— 一展开就把 Markdown 编辑区挤走，用户在"看诊断"和"改内容"
之间来回打架；右栏只有一个 iframe，屏幕右半永远是一张 PDF。

## 2. 重设计的三条原则

1. **三栏工作台（借鉴 NotebookLM）**：左＝来源／材料，中＝主工作区（编辑 + 结论），右＝成果卡片。
   每栏职责单一，视线从左到右就是产品的数据流：材料 → 排版 → PDF。
2. **一切二级界面居中弹窗**：右栏（以及顶栏、结论条）里的卡片都是**入口**，点开后在屏幕正中央
   弹出全功能面板。原地展开的 `<details>` 全部废弃 —— 二级内容不再挤压一级内容。
3. **Organic 视觉语言，工作台密度**：颜色、圆角、字体全部取 Organic token；但间距压到工作台级
   （padding 12–18px、字号 12–14px），不使用 Organic 演示页那种大留白。

## 3. 视觉系统（全部来自 Organic tokens，禁止硬编码新色值）

样式表：`_ds/organic-.../styles.css`（实现时把它作为全局样式引入，替换 `global.css` 的旧 token）。

| 用途 | token |
| --- | --- |
| 页面底色 | `--color-bg` #f5ead8 |
| 卡片／面板／侧栏 | `--color-surface` #ebddc5 |
| 编辑器"纸面"、弹窗内区块 | `--color-neutral-100` #f9f4ed |
| 主操作（生成 PDF、下载、采用） | `--color-accent` #c67139，hover `-600`，active `-700` |
| 成功／达标／填充条正常 | `--color-accent-2-*`（沙绿，`-100` 底 `-800` 字） |
| 警告／未达标／超高块 | `--color-accent-*`（赤陶，`-100` 底 `-800` 字） |
| 次要文字 | `color-mix(in srgb, var(--color-text) 45–62%, transparent)` |
| 圆角 | 卡片 `32px`（`.card`）、弹窗 `32px`（`.dialog`）、内部区块 `20px`、按钮/输入 `999px` |
| 阴影 | `--shadow-sm` 常态卡片、`--shadow-md` hover、`--shadow-lg` 弹窗 |
| 字体 | 标题 `Caprasimo` → 中文回落 `Noto Sans SC`；正文 `Figtree` + `Noto Sans SC`；代码/Markdown `ui-monospace, Menlo` |

**复用的 DS 类**：`.card` `.card-kicker` `.btn .btn-primary .btn-secondary .btn-ghost .btn-icon`
`.tag .tag-accent .tag-accent-2 .tag-neutral` `.input` `.field` `.seg .seg-opt` `.table`
`.dialog .dialog-title .dialog-actions` `.elev-sm/md/lg`。
图标：Lucide 线性图标，`stroke-width: 2.75`（Organic 规定），尺寸 15–17px。

**交互态**：hover 走 accent ramp 上一档或 `--color-neutral-300`；键盘焦点用 DS 自带
`:focus-visible { outline: 2px solid var(--color-accent) }`，不得留浏览器默认蓝框。

## 4. 布局（NotebookLM 式三面板）

每栏是一个**独立面板**：`background: var(--color-surface)`、`border-radius: 28px`、
`height: calc(100vh - 78px)`、`overflow:hidden`，顶部一行面板标题（16–17px Caprasimo/中文回落）
＋右侧状态 tag 或 `⋮` 按钮，下面是可滚动的面板正文。面板内部再切成**小功能块**：
`border-radius: 20–22px`、`background: var(--color-neutral-100)`（或沙绿 `--color-accent-2-100`
标注开发者/次要功能），每块自带一行小标题。这一层嵌套是 NotebookLM 语言的核心。

```
┌ header ────────────────────────────────────────────────────────────┐
│ ● HalfHalf  半开卷小抄工作台            [高级选项] [AI 设置]        │
├─「材料」──────────┬─「排版」─────────────┬─「成果」───────────────┤
│ [+ 添加材料]      │ [Markdown 块]        │ 瓦片 2×3：             │
│ ┌ 小块: 材料转换 ┐│  纸面 textarea       │  PDF预览 | AI精简      │
│ │ 说明 + 两按钮  ││                      │  引擎详情 | 块诊断     │
│ └────────────────┘│ [loading / 出错 /    │  会话历史 | 排版参数   │
│ ┌ 小块: 测试材料 ┐│  结论条 + warning]   │ ── 分隔 ──             │
│ │ (dev, 沙绿)    ││                      │ 输出区：A4 缩略图      │
│ └────────────────┘│                      │  + 文件名 + 下载 PDF   │
│ ┌ 小块: 内容画像 ┐│ ┌ 底部动作条 ───────┐│ 空态：图标 + 「排好的  │
│ └────────────────┘│ │ 目标页数 −2+ ·     ││  PDF 会保存在这里」    │
│ 空态：图标+说明   │ │ 边距/方向 · AI精简 ││                        │
│                   │ │ · [生成 PDF →]     ││                        │
└───────────────────┴─└────────────────────┘┴────────────────────────┘
```

- 外层 `display:flex; flex-wrap:wrap; gap:12px; padding:0 18px 18px`；
  栏宽 `flex:1 1 300px / 2 1 520px / 1 1 320px`，左右栏 `max-width:420–440px`。
- 响应式靠 `flex-basis + min-width` 自然换行，**不需要媒体查询**：≥1300px 三栏并排；
  ~1000px 成果栏换行到下方；<760px 三个面板堆叠为单栏，顺序 材料 → 排版 → 成果。
- 中栏底部动作条＝NotebookLM composer 的位置：一条 `border-radius:28px` 的
  `--color-neutral-100` 胶囊，内含目标页数步进器、参数摘要 chip、AI 精简、主按钮「生成 PDF →」。
- 右栏瓦片＝NotebookLM Studio 的瓦片：`1fr 1fr` 网格、`border-radius:20px`、
  图标在上标题在下＋右侧 chevron，赤陶／沙绿两种底色交替，全部点开为**居中弹窗**。
- 空状态统一为「居中图标 + 一行粗体结论 + 一句解释」（对应 NotebookLM 的
  "Saved sources will appear here" / "Studio output will be saved here"）。

## 5. 组件级映射（旧 → 新）

| 旧界面元素 | 新位置 | 形态 |
| --- | --- | --- |
| ChatIntake `<details>` | 左栏顶部「+ 添加材料」＋「材料转换」小块 | **居中弹窗**（680px）：原始材料 textarea、转换按钮、流式状态、`<pre>` 流式预览、体检 tag、`仅写入编辑器` / `采用并排版` |
| 目标页数 `<input type=number>` | 中栏底部动作条 | 步进器：`−` 数字 `+`，仍钳制 1–50 |
| `插入图片` | 左栏「材料转换」小块内 | 次按钮 + 隐藏 file input（逻辑不变：读成 data URI 插到光标处） |
| `生成 PDF` | 中栏底部动作条右端 | `.btn-primary` + 右箭头，busy 时文案「排版中…」并禁用 |
| `✨ AI 精简` | 中栏底部动作条 + 右栏瓦片 | 瓦片右上角计数徽章显示待应用块数 |
| `AI 设置 ▾` 折叠 | 顶栏按钮 | **居中弹窗**（560px）：端点／模型／Key + 隐私说明（仍写 localStorage：`hh.ai.endpoint/model/key`） |
| `高级选项 ▾` 折叠 | 顶栏、中栏 `⋮`、中栏底部参数 chip、右栏「排版参数」瓦片 | **居中弹窗**（760px）：场景＝6 张**可选卡片**（标题＋一句解释，选中＝accent-100 底 + accent 描边 + ✓，仿 NotebookLM 的 Detailed Deck / Presenter Slides），学科 select、方向 `.seg`、边距 select，三个开关各带一行解释；右下「保存并重新生成」 |
| fixtures 速载 | 左栏沙绿卡（仅 dev） | select + 载入按钮；接口 404 时整卡隐藏（逻辑不变） |
| AI 建议列表 | 右栏卡片 | **居中弹窗**（880px）：汇总 tag、逐块 checkbox + 左右 diff（原文=surface／建议=accent-100）、被安全网拦截的块 checkbox 禁用并显示原因、右上「应用选中（n 块）」「放弃」 |
| 结论行 | 中栏结论条 | 沙绿=达标／赤陶=未达标，大标题 + 副句 + 全部 warning 列表 + 三个 ghost 入口 |
| `<details>` 引擎详情 | 右栏卡片 | **居中弹窗**（700px）：统计方块阵、推荐场景+理由、学科识别建议、rule trace（硬/软/裁决三色 tag）、结果 + 二分搜索轨迹 |
| `<details>` 块诊断 | 右栏卡片 | **居中弹窗**（860px）：每页填充条（<60% 灰／正常沙绿／>100% 赤陶）+ 块表格（超高=赤陶行底，缩过可读限=沙绿行底） |
| `<details>` 会话历史 | 右栏卡片 | **居中弹窗**（760px）：表格 + Δ 字号（涨=沙绿、跌=赤陶）+ 清空 |
| 引擎详情 / 块诊断 / 会话历史 / AI 精简 / 排版参数 / PDF 预览 | 右栏 2×3 瓦片网格 | 图标在上、标题在下＋ chevron；赤陶／沙绿底色交替；全部点开为居中弹窗 |
| 右栏 PDF `<iframe>` | 右栏瓦片下方的输出区 | 卡内是 A4 比例缩略图，点击 → **居中弹窗**（760px）里逐页大图 + 下载。实现时缩略图与大图都用 blob URL 的 `<iframe>`（大图 `#page=N`），设计稿里画的是版面示意 |
| 空状态「生成后在这里预览 PDF」 | 同上 | 虚线 A4 框 + 「点击可放大到居中窗口」 |

**弹窗统一规格**：`position:fixed; inset:0; z-index:120; display:grid; place-items:center;
padding:24px; background:color-mix(in srgb, var(--color-neutral-900) 55%, transparent)`；
点遮罩关闭（内层 `stopPropagation`），标题行右侧 `.btn-icon` 关闭；`max-height:92vh`，
超长内容在弹窗内部滚动，不让页面滚。实现时另加：`Esc` 关闭、打开时锁 body 滚动、
`role="dialog" aria-modal="true"`、焦点移入弹窗、关闭后焦点回到触发卡片。

## 6. 状态机（与后端接口的对应）

单一 `modal: null | 'intake' | 'advanced' | 'ai' | 'sug' | 'engine' | 'diag' | 'history' | 'pdf'`
控制全部弹窗（同一时刻只有一个）。其余状态与旧 `ScenePanel` 完全一致，字段名建议照搬。

| 用户动作 | 请求 | 界面反馈 |
| --- | --- | --- |
| 生成 PDF | `POST /api/scene`（markdown, targetPages, scene, orientation, debug, allowReorder, subject, marginMm, stretchFill）→ 再 `GET /api/download/:jobId/pdf` | 中栏 loading 条（赤陶底 + 旋转环）→ 结论条 + 右栏卡片全部填充 + 会话历史追加一行 |
| AI 精简 | `POST /api/ai/compress`（BYOK provider）| 无 key 时提示并打开「AI 设置」弹窗；返回后右栏出现建议卡，自动打开建议弹窗 |
| 材料转换 | `POST /api/ai/structurize`（SSE：delta/retry/result/error）| 弹窗内流式 `<pre>` 追加；`retry` 事件把状态换成「结构体检未过，AI 修正中（…）」；`result` 后出现体检 tag 与采用按钮 |
| 采用并排版 | 写回 markdown 后立即调用 `/api/scene`（沿用旧 `mdOverride` 传参绕过闭包） | 关闭弹窗 → 中栏 loading |
| 测试材料载入 | `GET /api/fixtures` / `GET /api/fixtures/:name` | 404 时整卡隐藏 |
| 任意 401 | `apiFetch` 弹口令 prompt 并重试 | 保持原逻辑（可改成 Organic 风格的口令弹窗，非必须） |

**演示稿的差异**：设计稿用假数据（`demoState` 属性切换 空／排版中／成功／未达标／出错），
材料转换用定时器模拟 SSE。落地时把这些替换成上表的真实请求即可，**不要改布局与样式**。

## 7. 实现清单（落回 React 的顺序）

1. 引入 Organic `styles.css`，删掉 `global.css` 里的旧 token（保留 `*` reset 与中文字体回落）。
2. `AppLayout.tsx`：换成新 header（圆形 accent 徽标 + 品牌 + 副标题 + 高级选项／AI 设置按钮），
   把 `modal` 状态提到 `ScenePanel`（或一个 `useModal` hook）。
3. 拆 `ScenePanel.tsx`：`SourceRail`（左）、`EditorPane`（中）、`OutputRail`（右）、
   `modals/` 下八个弹窗组件。请求逻辑原样搬迁，不改字段。
4. 通用 `<Modal title width onClose>`：遮罩、Esc、body 滚动锁、焦点管理。
5. 逐屏对照设计稿核对：空状态、排版中、成功、未达标（含三条 warning）、AI 建议、材料转换流式、出错。
6. 可访问性：所有卡片入口是 `<button>`；表格保留 `<th>`；checkbox/select 用原生元素（DS 类已配好样式）。

---

## 8. 明确不做的事

- 不新增任何后端接口、不改请求体字段、不删除任何现有功能（含 debug 网格、乱序、fixtures、诊断表）。
- 不改 Markdown 编辑区的本质：仍是纯 `textarea`（等宽字体 + 粘贴图片），只是换了纸面容器。
- 不引入图表库、不画装饰性插画；A4 预览示意仅用于无后端的设计稿。
- 不使用 Organic 之外的颜色、字体、圆角。
